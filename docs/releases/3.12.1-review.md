## Disposition key

**Correction** means existing guidance needs a scoped change and associated eval coverage.
**Handled** means current guidance makes no conflicting assumption and need not be rewritten for this cue alone.
**Deferred** means the cue concerns a separate capability or operational procedure.
These are review dispositions, not declarations that implementation or live checks passed.

## Additional claim-driven corrections

The release notes are additional cues, not the complete compatibility test list.
The following existing-path corrections come directly from the ledger:

- Query results and error bodies: `claim-20261015-0101`–`0106`, `0111`–`0112`, and `0119`–`0122` distinguish SQL planning failure, InfluxQL unknown-table results, empty results, unknown databases, and absent routes.
  Keep the skill explanation behavioral; link to the API spec for complete shapes.
- Scoped access and health checks: `claim-20261015-0113`–`0118` require distinguishing reachability, authorization, and visible database inventory.
  An empty `403` does not distinguish a denied database from a nonexistent one.
- Plugin-file HTTP operations: RC-2 `claim-20260930-0210` refutes the current raw upload guidance and `0211` confirms JSON creation in that run.
  Correct existing guidance only after its 3.12.1 contract is checked; do not add a full endpoint reference.
- Partial writes: current application guidance already distinguishes V3 from legacy endpoints.
  RC-2 `claim-20260930-0324`–`0328` and `0405`–`0406` support that distinction but do not expand its recorded live version to 3.12.1.

## Conflicts and completion conditions

The published release and upgrade pages describe automatic 3.12 catalog commitment as universally blocking 3.11 rollback and suggest catalog restoration.
GA claims `claim-20261007-0400`–`0403` are narrower and contradict that universal account: one binary swap worked before an incompatible record, while restoring an old catalog alongside newer data returned another table's rows.
These observations do not establish a supported rollback path.
Upgrade/rollback procedures remain deferred; neither skill should reproduce the published catalog-only recipe as safe guidance.

Unknown ledger entries retain their verdicts.
Documented fixes do not erase narrower contrary observations without investigation.
Before certification, the baseline still needs exact-version coverage for any newly asserted executable contract, final-text full evals, required-case acceptance, applicable live examples, and cleanup records.
No probe, model run, or live example was performed to create this review record.
