# InfluxDB 3.12.1 release record

The compatibility review, evidence, and live checks behind influxdb3-skills 0.7.3, which brings both skills from Core and Enterprise 3.11.5 to 3.12.1.
The specification is [issue #35](https://github.com/influxdata/influxdb3-skills/issues/35).
Reasons for each skill change are in [CHANGELOG.md](../../CHANGELOG.md), eval results in [eval-history.md](../eval-history.md) and [`evals/evidence/v0.7.3/`](../../evals/evidence/v0.7.3/), and the release gate in [publishing.md](../publishing.md).

## Live checks

Run on 2026-11-09 against the release skills tree at `796c769`.

### Environment

- InfluxDB 3 Core 3.12.1 in Docker at `http://127.0.0.1:8282`, with `INFLUXDB3_PLUGIN_DIR=/plugins` and a five-database limit.
- InfluxDB 3 Enterprise 3.12.1 in Docker at `http://127.0.0.1:8181`, with `--plugin-dir=/plugins`.
- `influxdb3` CLI 3.12.2.

### Order

These checks ran after the release eval suites, not before them.
No check found a defect that blocks the release, so the eval evidence stands.
Every defect found needs a change under `skills/`, so each one is deferred to 0.7.4.
A separate change makes release verification reject evals that start before the live checks finish.

### Results

| Check | Result |
|---|---|
| Application examples on Core | Pass. `diagnose.py` reported a 422 as a missing admin scope; the server had reached its database limit. Run alone, it reported full health OK. See #41. |
| Admin examples on Enterprise (HTTP and Python) | Pass. Each lifecycle completed and its orphan check found no databases or tokens left. |
| Orphan checks before and after | Clean on both servers. |
| Plugin round trips and troubleshooting pairs | 10 of 12 pass. The gaps are in #42 and #43. |
| Smoke prompts (`evals/smoke-prompts.md`) | 12 pass, 14 pass with a note, and 4 fail. Prompts 7, 8, 10, and 24 didn't name InfluxDB, so the skill didn't load. No hard-block violations. The prompts now name InfluxDB 3. |

### Issues filed for 0.7.4

- #41: `diagnose.py` reports a Core database-limit 422 as a missing admin scope.
- #42: `quirks.md` entry 4 parses `system.tokens.permissions` as JSON. Core 3.12.1 returns a bare string, so the parse crashes.
- #43: example and README gaps: the `tokens_permissions_parse` pair, the scheduled-plugin log line, `silent_auto_create` cleanup, and uploaded plugin files left behind.
- #44: `testing.md` tells agents to create the trigger before the offline test.
